## Dependencies that prevent simple deletion

1. **Account unlinking is not erasure.** participants.auth_user_id uses ON DELETE SET NULL. Profiles and Auth accounts have separate links; actor foreign keys may become NULL or block deletion. Revocation/session handling is a separate security operation.
2. **Cascade paths cross official case boundaries.** Participant -> profile/event participation; event participation -> applications/interviews; application -> employment_outcomes -> follow_ups. Direct participant application FKs use RESTRICT. The 2026-10-16 recruitment-provenance milestone now rejects linked participation/offering removal and vacancy ownership transfer before their existing FK actions can erase or reassign history; it does not replace the FKs or install a disposition bypass. Program references can also block downstream deletion. Other record/copy paths still require an exact manifest and actual dependency inspection before any future approved disposition.
3. **Polymorphic links require explicit inventory.** AI runs/suggestions and embeddings identify source entities without source FKs; audit record_id, JSON snapshots, history, program request responses and Storage path text cannot be safely handled by an FK cascade alone.
4. **Resume reference protection is narrower than case preservation.** It prevents deletion while a current profile points at a file. It does not preserve a resume version submitted in a historical case. No old-file cleanup was exercised in this milestone.
5. **Staleness is not disposal.** An invalidated embedding retains source text; lease expiry retains an AI source snapshot; rejection retains AI evidence; application withdrawal retains the application.
6. **Retention state does not exist across access paths.** Do not reuse profiles.is_active (account activation), vacancy.is_active/platform_status, verification_status or an MFA recovery hold as a legal records hold. A future restriction must cover matching, application views, Storage, RPCs, extraction and exports while preserving lawful case access.

## Government case record versus processing copy

Working classification for appraisal: submitted applications/referrals, attendance/service delivery, interviews/outcomes/follow-ups, accreditation decisions and supporting documents, publication/change evidence and their necessary consent/decision records are **presumptive official service/case records**. Profile/qualification versions and resumes relied upon in a case may be supporting case evidence. The Provincial Records Officer must identify the official record copy, series, trigger and archival value; a database table name does not settle the classification.

AI source snapshots, rejected proposals, stale vectors, browser caches, staging and duplicate exports are **candidate processing/duplicate records**, not automatically disposable or outside public-record controls. They may become evidence of a decision, error, complaint, audit or incident. Preserve an item under applicable hold and request appraisal before adopting a shorter working-copy period.

The NPC retention principles tie retention to purpose and lawful requirements; they do not approve a blanket five-year deadline. NAP guidance requires proper records authority before government-record destruction. These are the basis for the inactive design, not a legal opinion on Cagayan's specific series. [NPC IRR section 19](https://privacy.gov.ph/implementing-rules%20regulations-data-privacy-act-2012/), [NAP records FAQ](https://nationalarchives.gov.ph/frequently-asked-question), [NAP General Circular 5](https://nationalarchives.gov.ph/wp-content/uploads/2024/02/NAP_General_Circular_No_5.pdf).
